VIEW SOURCE ↗

Mechanism - SAST Framework

Framework de SAST desenvolvido do zero para analisar código-fonte, identificar padrões de risco e integrar os resultados ao ciclo de segurança. O projeto combina análise por regex, plugins especializados, tratamento de falsos positivos, geração de evidências e integração automatizada com uma plataforma de gestão de vulnerabilidades.

O problema

Criar uma camada própria de análise estática que pudesse ser executada dentro do pipeline, encontrar padrões de segurança específicos e entregar os resultados de forma estruturada para o processo de tratamento de vulnerabilidades.

O projeto foi desenhado para ser extensível: novas regras podem ser adicionadas por configuração e novas capacidades podem entrar como plugins.

O que foi construído

  • Scanner que percorre o repositório e filtra arquivos por extensão.
  • Engine de regras baseada em expressões regulares.
  • Metadados de finding com risco, vulnerabilidade, CWE e CVE.
  • Filtro de falsos positivos por conteúdo e caminho.
  • Plugin para validação de CPF e exposição de informação sensível.
  • Camada opcional de validação de findings com modelo de IA.
  • Conversão dos resultados para formato consumível pelo DefectDojo.
  • Criação/consulta automatizada de produto, engagement e scans.
  • Modo offline para geração local de relatórios.
  • Execução integrada ao Bitbucket Pipelines com artefatos JSON.

Honeypot & Automated Blocking

Honeypot desenvolvido para receber requisições em endpoints controlados, registrar comportamento de acesso e alimentar um mecanismo automatizado de bloqueio.

O problema

Detectar automação maliciosa e transformar sinais de ataque em uma resposta rápida, sem depender de uma chamada externa para cada request e sem sobrecarregar a camada de bloqueio.

O desenho prioriza resiliência: eventos entram em fila, são processados em lote e o estado da network list é mantido localmente antes da sincronização.

O que foi construído

  • Templates e endpoints falsos para simular superfícies reais.
  • Logs estruturados com IP, path, User-Agent e timestamp.
  • Fila Redis para absorver picos de requisições.
  • Workers concorrentes para processamento assíncrono.
  • Batching de IPs e flush periódico para reduzir chamadas externas.
  • Sincronização com network list e tratamento de retries.
  • Persistência local e atualização periódica da lista.
  • Execução containerizada via Docker Compose.

Objetivo

Reduzir tarefas manuais na operação de segurança e criar mecanismos repetíveis para verificar a cobertura de segurança de múltiplos repositórios.

Exemplos

  • Inventário automatizado de repositórios.
  • Validação de workflows de segurança.
  • Checks automatizados de versões e CVEs.
  • Integração com GitHub Actions e ferramentas de desenvolvimento.
  • Resumos de segurança diretamente no pipeline.
